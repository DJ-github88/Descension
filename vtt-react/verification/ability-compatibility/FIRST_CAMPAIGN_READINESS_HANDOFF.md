## 2. Checker Boundary Corrections Made

To avoid equating *"not accepted by this adapter"* with *"requires new architecture,"* `checkAbilityCompatibility.cjs` now separates every exclusion and prerequisite across **five distinct categories** (`EXCLUSION_CATEGORIES`):

1. `missing_engine_capability`: Record genuinely requires a runtime combat/consequence mechanic not present in accepted execution profiles (multi-round duration/buff/debuff/DoT/HoT/shield, saving throw mitigation, AoE/cone/line/chain/multi-target routing, simultaneous damage+healing, reaction/trigger windows, summon/transformation/utility/cleanse, non-linear/missing-HP formulas, or class resources with no revisioned server room home).
2. `incompatible_authored_schema`: Underlying gameplay mechanic is already supported by an accepted profile or existing planner, but the authored JSON schema uses keys/envelopes rejected by strict key whitelists in `spellConsequence.supportShape` or `encodingConflict`.
3. `intentional_manual_only`: Record is explicitly designated `manualOnly: true`, `authoredOnly: true`, `executionEnabled: false`, or `applicationMode: "manual-tabletop"` (such as the **818** reconstructed CR-1 class records).
4. `conflicting_data`: Record contains internal authored contradictions (e.g., `resourceCost.spheres` vs `resourceCost.resourceValues.*_sphere` on **13** Arcanoneer spells; base `classResource.cost` vs top-level `devotionCost` on **12** Martyr spells; generic `classResource.cost: 3` vs `musicalCombo.requires` note count on **19** Minstrel cadences; or `damageConfig.formula` vs `specialMechanics.scalingDamage` on `martyr_redemption_strike`).
5. `runtime_prerequisites_offline_unknown`: Runtime state that an offline static checker cannot establish (room registry admission `actor_authored_admit`, owner roll/payment approval, GM confirmation, map token placement, live sphere/note/devotion bank affordability, and Cross-Track Finding I2 raw-vs-effective attribute consumption in `spellConsequence.js`).
