## Cohort selection

**Core directions accepted for prototype development; cohort/tuning details remain provisional:** Gambler's escrow/hand, Druid's anatomical slots and existing sphere/note paths are useful asymmetric test cases. The current handoff implements none of those domains: it is correction/definition infrastructure only. Fate Weaver/Deathcaller wait for real interception/entity dependencies rather than shipping decorative previews as working classes.

Mandatory restoration does not mean all three probability classes must share one implementation task. A class's spells/trees/heritage/UI can be separate bounded units, but the class is not playtest-ready until all required units and its actual combat scope are complete.

## Avoid an architectural second project

Reuse P7 authority, existing domain planners, P5/P6 persistence/custody, existing class data views and Calm palette. Add the smallest typed seams needed by demonstrated prototypes. Do not replace Zustand, socket transport, canonical character codecs, every HUD component or the combat engine as a precondition to class design.

## Contract readiness

CR1 onward cannot yet be handed to DeepSeek as final executable application contracts. Exact operation schemas, all native variants, remaining dossiers, full new spell libraries and ID transfers are unfinished. Filling those blanks during coding would violate the purpose of this assignment.
