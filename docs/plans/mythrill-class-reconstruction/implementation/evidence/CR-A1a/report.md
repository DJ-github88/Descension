## 5. Implementation notes, interpretations and deviations

- `emptyRegistry(roomId)` returns the snapshot object directly on success (contract literal
  "valid revision0 snapshot | `{ok:false,code}`"), failure object on invalid room.
- Malformed planner/describe envelopes use `INVALID_DEFINITION` (no dedicated frozen code for
  envelope shape); unsupported-but-well-formed literals use `UNSUPPORTED_SHAPE`/`UNSUPPORTED_BINDING`.
- `describe` check order: room scope → found → hash → binding → revoked (contract §7.6 order:
  "unknown, modified, mismatched or latest-revoked").
- Scope and semantic checks run after `authorize` against the detached snapshots per HeadQ 1.4
  ("After the await, use only those validated private snapshots for scope, hashes, replay,
  expected-revision, version/revocation checks") and §7.3 ("validate/detach, then freshly
  authorize, resolve replay, then revision/hash/transition checks"). Only structural validation,
  detachment and complete registry-history validation run pre-await; malformed inputs and corrupt
  registries fail before the authorizer is invoked.
- Authority mapping: missing/false/thrown/malformed/stale/non-matching-policy →
  `AUTHORITY_UNAVAILABLE`; unbound principal or `uid!==gmUid` → `FORBIDDEN`; result room mismatch →
  `SCOPE_MISMATCH`. Extra authorizer fields are ignored; every required field is validated.
- `requestHash` is `canonicalHash` of the entire detached validated request (never client-provided);
  decision hashes are recomputed on every snapshot validation with
  `expectedRegistryRevision = sequence − 1`. Scope-mismatch requests are rejected before replay
  resolution so foreign-room request IDs are never probed.
- Capacity is enforced as ≤128 definition versions, ≤256 decisions and ≤256 KiB rebuilt-snapshot
  bytes, all → `CAPACITY` with no eviction. Boundary observed: with the mandated UUID/hash
  lengths, a 256-decision history cannot also fit the 256 KiB budget (empirically the byte budget
  binds first: ~245 decisions with minimized content), so the planner-driven 256-decision count
  path is unreachable for any valid content; the count caps are therefore proven as
  defense-in-depth through every snapshot consumer with padded over-count snapshots. This is a
  contract-consistent consequence of two frozen caps, not a deviation; both caps are tested.
- Server files run sloppy-mode per `server/.eslintrc.js` (`sourceType:'module'`, no `'use strict'`
  directive allowed), so frozen-mutation assertions use `Reflect.set` + value checks instead of
  `assert.throws`.
